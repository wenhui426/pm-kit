# pm-kit

面向产品经理的通用 Skill 包：通过一个入口，根据本次目标、已有材料和交付要求，选择能力、组合工作流，并生成产品文档、交互规格、原型或评审结果。

你可以从一句想法、一张截图、一份 HTML 或已有 PRD 开始。需求不完整时先澄清；已有合格材料时直接进入相应阶段。场景、模板、组件规范和案例可以持续增加。

## 快速开始

### 1. 下载完整技能包

下载或克隆本仓库，保留整个 `pm-kit` 文件夹及内部相对路径。若仓库根目录就是本技能包，根目录中应直接包含 `SKILL.md`、`capabilities/`、`modules/` 等文件和目录。

`SKILL.md` 是 AI 的入口；本 README 面向使用者。只复制入口文件会丢失工作流、模板、规范和脚本。

### 2. 让 AI 读取入口

在支持读取本地文件的 AI Agent 中，将下面的路径换成自己的实际位置：

```text
读取 <pm-kit 的绝对路径>/SKILL.md，按 pm-kit 处理本次任务。

材料：这份会议纪要和客服反馈。
目标：梳理订单取消功能，供设计、研发、测试评审。
交付：Markdown PRD。
范围：只处理未发货订单；其他情况先列为待确认。
输出位置：<项目目录>/outputs/。
```

使用 Codex 时，也可以在适用范围内的 `AGENTS.md` 中加入下面的说明，并将占位路径替换为实际绝对路径：

```md
产品经理相关任务统一从 `<pm-kit 的绝对路径>` 启动：先读取该目录下的 `SKILL.md`，再按本次目标、输入材料和交付要求选择流程、模板及包内模块。适用于需求澄清、产品方案、PRD、交互、原型、评审及组合交付。
```

全局 `AGENTS.md` 用于个人默认规则；项目级文件用于限定项目范围。通过规则引用外部入口即可使用此包。若希望通过原生技能列表发现或用 `$pm-kit` 调用，还需按所用工具支持的技能目录方式安装完整文件夹；不同工具的发现方式可能不同。

### 3. 说明本次目标

通常给出四项信息即可开工：材料、目标、交付物、范围或限制。明确的任务直接执行；缺失信息会改变业务规则或结果时，Agent 会提出需要你判断的选择。

## 适合处理哪些工作

| 任务 | 常见输入 | 交付物 |
| --- | --- | --- |
| 材料分析与需求澄清 | 截图、会议纪要、客服反馈、文字想法 | 来源清单、问题、冲突、需求简表 |
| 竞品分析 | 产品名、赛道、待解决的问题、截图、HTML、文档或链接 | 本地对照表、调研简报或深度报告，默认 Markdown |
| 产品规划 | 业务目标、用户问题、现有方案 | 产品方案、MVP、范围、指标口径与风险 |
| PRD 编写与修订 | 已确认需求、旧 PRD、评审意见 | Markdown PRD、修订说明、验收标准 |
| 交互设计 | PRD、页面、流程描述 | 信息架构、用户流程、页面规格、状态与权限 |
| 流程图与泳道图 | 已确认业务说明、PRD、角色和分支条件 | 可编辑 draw.io、离线 SVG HTML、浏览器可用时的 PNG |
| 原型探索与交付 | 文字目标、截图、HTML、页面规格 | 单文件 HTML 或明确要求的 React 工程 |
| 产品评审 | 需求、原型或实现 | 分级问题、证据、修复建议、验收清单 |
| 变更与连续项目 | 已有产物、规则版本、修改要求 | 影响分析、更新产物、规则和依赖记录 |

默认文档格式为 Markdown，默认原型为可离线打开的单文件 HTML。需要 React 工程、Word 或其他格式时，请在任务中明确说明。Word、PDF、演示文稿等文件的生成和排版验证，需要运行环境提供相应工具。

当前重点覆盖竞品分析、需求到原型、评审和变更交接。用户研究、路线图和上线后实验可以整理给定材料，但尚未全部提供独立专项流程。纯视觉素材制作、无产品目标的代码修复和外部系统集成不属于本包的主要范围。

## 使用示例

### 分析截图

```text
使用 pm-kit 分析这张订单后台截图。
检查筛选、信息层级和批量操作，输出带证据的问题清单。
本轮只做分析。
```

### 从需求生成 PRD 与原型

```text
使用 pm-kit，根据会议纪要和一线反馈设计门店巡检问题闭环。
先澄清会改变流程的规则，再输出 PRD、交互规格和单文件 HTML 原型。
覆盖分派、整改提交、复核通过、退回和重开。
文件放到我指定的项目目录，完成后检查各产物是否一致。
```

### 使用自己的模板

```text
使用 pm-kit，把这份需求整理为 PRD。
按我提供的团队模板填写，保留模板规定的章节和字段。
材料不支持的内容标记为待确认，不编造数据。
```

### 继续项目或开启新任务

```text
继续项目 <项目 ID>，本轮新建任务 <任务 ID>。
沿用该项目已确认的业务规则，梳理总部周报的指标口径。
不要继承其他任务尚未确认的假设。
```

## 内部如何工作

Agent 先识别目标产物和输入成熟度，再从 [能力清单](capabilities/registry.json) 选择需要的阶段。每个阶段读取对应说明，完成产物与检查后，再判断下一阶段。

例如，模糊需求可能经过：

```text
材料分析 → 需求澄清 → 产品规划 → PRD → 交互设计 → 原型 → 检查与交付
```

已有确认版 PRD 时，可以直接进入交互设计或原型阶段。只要求检查页面时，通常只执行材料分析与评审。遇到来源冲突或会改变范围的选择时，Agent 会说明可选路径及影响，等待用户决定。

包内专项模块：

| 模块 | 适用任务 |
| --- | --- |
| `make-prd` | 从产品规划到 PRD 审查修订的完整六步流程，带阶段确认 |
| `prd-html` | 持续维护页面规格、设计规范与逐页验收的多页面原型 |
| `html-prd` | 从现有 HTML 反向整理 PRD 或评审文档 |
| `flowchart-diagram` | 普通流程图、多角色泳道图、矩阵泳道和独立图文件交付 |

专项模块已包含在 `modules/` 中，无需另行安装同名技能。日常任务可以使用简明流程；选择模块时按其说明执行。

运行调度由当前 AI Agent 完成。`SKILL.md` 提供规则，无法独立启动程序；是否能使用子 Agent、浏览器或其他工具，取决于运行环境。

## 个性化与扩展

工作能力与交付资源分别维护：

| 想调整的内容 | 维护位置 |
| --- | --- |
| 仅本轮使用一份模板 | 在任务中直接指定模板文件路径 |
| 当前项目专用模板 | `<项目根目录>/.pm-kit/templates/<slug>/` |
| 团队或个人长期模板 | `catalog/local/templates/` |
| 行业角色、流程和业务状态 | `catalog/local/scenarios/` |
| 组件映射与视觉规范 | `catalog/local/component-libraries/` |
| 脱敏后的可复用案例 | `catalog/local/cases/` |
| 新增处理能力或工作流程 | 登记 `capabilities/registry.json` 并提供执行说明，按扩展手册补充路由与评测 |

模板优先级为：本轮明确指定 → 当前项目模板 → 团队或个人模板 → 内置模板。高优先级规则覆盖同名字段或章节，不冲突的必要要求继续保留；无法并存的要求交由用户选择。

新增资源通常包含 `manifest.json` 和说明文件，通过触发词、适用范围、格式和版本参与匹配。可以继承一个同类型资源，再补充差异。新资源从 `draft` 开始，检查与复用后再提升状态。

也可以用自然语言提出扩展要求：

```text
把这份已验收 PRD 的章节与字段整理成团队模板。
先列出适用范围、必填项和需要脱敏的内容。
确认后保存到 catalog/local/templates/，并完成目录校验与索引更新。
```

升级技能时保留自己的 `catalog/local/`。详细操作见 [扩展操作手册](references/extension-playbook.md) 和 [扩展协议](references/extension-protocol.md)。

## 跨轮记录与任务隔离

需要持续修改、分阶段确认、追踪依赖或跨轮接续时，pm-kit 维护项目和任务记录：

- 项目层保存带来源、确认状态和版本的共用业务规则。
- 任务层保存该任务的决定、假设、待确认事项和运行断点。
- 产物索引记录依赖的规则与上游产物版本；依据变化后，相关产物标记为待复查。
- 每轮执行“读依据 → 做任务 → 对照检查 → 写回变更”。

同一聊天不自动代表同一项目。同项目的新任务可以共享已确认的项目规则；其他任务的草稿和假设不自动共享。一次性任务无需强制创建持久记录。

规则与目录详见 [跨轮协议](references/cross-round-protocol.md)；机器可检查的格式见 [记录数据契约](references/record-contract.md)。

## 环境与校验

日常使用需要能读取本地文件的 AI Agent。处理截图需要图像理解能力；验证原型需要浏览器；生成工程或特定文件格式需要相应运行工具。

流程图模块的 draw.io → SVG HTML 脚本只依赖 Python 标准库；PNG 还需要本机 Chrome、Edge 或 Chromium，可指定浏览器路径。只需文字或简短 Mermaid 时不强制生成图文件。默认格式、导出命令及基础图形支持范围见 [flowchart-diagram 模块说明](modules/flowchart-diagram/README.md)。

资源和记录校验使用 Python；完整 Schema 校验需要 `jsonschema`。如需运行校验工具，可在自己的 Python 环境中安装：

```sh
python -m pip install "jsonschema>=4.18"
```

在 `pm-kit` 根目录运行：

```sh
# 查看可发现资源
python -X utf8 scripts/catalog_manager.py discover

# 校验清单结构、路径和继承关系
python -X utf8 scripts/catalog_manager.py validate

# 新增或更新资源后重新生成索引
python -X utf8 scripts/catalog_manager.py rebuild-index

# 只读校验业务记录；将占位路径换成项目集合或单项目目录
python -X utf8 scripts/validate_records.py "<业务记录目录>"
```

结构校验不判断业务规则是否正确，也不代替文档回读、浏览器预览和交互验收。无法执行的检查应在交付中说明。

## 分享与贡献

分享时保留完整技能包。项目产物与业务记录建议放在技能包之外；公开发布前检查 `catalog/local/` 中是否包含个人模板、客户材料或其他未授权公开的内容。

提交扩展建议时，请附上一个具体任务、输入材料类型、期望交付物和当前流程的不足。新增能力按 [扩展操作手册](references/extension-playbook.md) 执行；只调整团队格式时优先新增模板。
