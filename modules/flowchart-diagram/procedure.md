# 流程图与泳道图

## 调用与交接

本模块由 pm-kit 的 `flowchart-diagram` 能力调用。本文件、示例、参考资料和脚本共同构成模块，不需要独立技能入口。

适用于用户要求普通流程图、泳道图、跨角色审批流或可编辑 draw.io 源文件。仅用文字说明步骤、PRD 中放简短 Mermaid 或生成页面原型时，继续使用相应简明能力；不要为每段流程文字自动创建三格式文件。

接收已有业务说明、PRD、交互规格或可观察的截图事实。记录来源和当前采用的规则；角色、审批条件、异常出口不明且影响结果时，先通过 `clarify-requirements` 澄清。已有确认流程时直接绘图，本模块没有额外固定的逐阶段确认节奏。

输出交给 `review-validate` 或 `deliver-change`，包含图类型、来源、角色/活动/分支清单、文件路径、验证情况与未决事项。与 PRD、原型组合交付时使用同一组名称和规则；跨轮保存按包级协议登记图文件依赖。

## 1. 选择图类与格式

- 一个角色或只需表达步骤和条件：普通流程图。
- 至少两个角色各自执行活动：泳道图，每个活动放在执行角色所在泳道。
- 用户需要“谁在哪个阶段做什么”：矩阵泳道，角色按行、阶段按列，使用矩形分区和文本标题；先确认阶段含义。

默认尝试交付 `.drawio`（可编辑）、`.html`（内嵌 SVG，离线浏览）、`.png`（高清图片，默认 2 倍）三种格式。用户明确只要某种格式时遵循指定范围。PNG 需要本机 Chrome、Edge 或 Chromium；环境缺失时交付可生成部分，并标注 PNG 未生成及原因。

这些产物是 BPMN 风格可视化。draw.io XML 不等于可执行 BPMN 文件，也没有通过 BPMN 2.0 语义认证。高级符号参考仅在任务需要时读取，不能把参考清单当作渲染器的完整支持声明。

## 2. 先建流程模型

1. 列参与方、触发条件、起点和结束条件。
2. 活动采用“动词 + 名词”，每个活动标明责任角色和业务来源。
3. 定义移交，跨泳道连线表示工作交接。
4. 判断分支写在连线上，说明通过、拒绝、退回、取消、超时等真实规则；未知规则用 `[NEEDS CLARIFICATION: 具体问题]` 标记。
5. 检查主路径和关键异常出口；允许合理重试或退回环，但必须说明如何退出，不能把循环强行画成一次结束。

按业务语义选择分支与合并，不强制所有网关成对；多个分支分别结束时可以使用各自结束事件。单图活动数建议不超过 15，超出时拆成总览和子流程并保留对应关系。角色较多时按职责或参与组织拆分，不能只为减少行数合并不同责任人。

## 3. 生成 draw.io 源文件

生成未压缩 XML：`mxfile → diagram → mxGraphModel → root → mxCell`。每个文件保留一个 `diagram`，多图分别生成文件。完整示例见 [EXAMPLES.md](EXAMPLES.md)。

普通图的元素挂在画布 `parent="1"`。泳道图采用 `Pool → Lane → 元素`：

- 池为画布子容器；泳道 `parent` 指向池，活动 `parent` 指向泳道。
- 容器标题使用 `swimlane;horizontal=0;startSize=30;`，泳道纵向堆叠。
- 元素坐标相对其直接父容器；连线通常挂在池层，`source`/`target` 指向活动 ID。
- 主流向从左到右，活动间距建议至少 40；回退线用正交折线并标记原因。
- 拥挤、跨泳道和回退连线显式提供 `mxGeometry/Array[@as="points"]/mxPoint` 折点；坐标相对连线父容器。必要时设置 `exitX/exitY` 和 `entryX/entryY`，避免穿过活动。
- 开始/结束用圆，任务用矩形，条件用菱形并通过子文本标记 `X` 或 `+`。颜色仅辅助表达，不替代角色、动作和条件标签。

符号细节按需读取：

- [元素参考](references/bpmn-elements.md)：任务、网关、池、数据对象。
- [事件参考](references/bpmn-events.md)：超时、消息、边界事件。
- [draw.io 样式参考](references/bpmn-drawio-styles.md)：样式串与尺寸示例。

## 4. 导出 HTML 与 PNG

以下命令中的 `<模块目录>` 为 `<pm-kit 根目录>/modules/flowchart-diagram`；输出目录沿用用户要求，输出名使用业务名称或版本号。脚本拒绝覆盖已有目标文件，重新生成时使用新版本路径。

```sh
python -B -X utf8 "<模块目录>/scripts/render_bpmn_html.py" "流程.drawio" "流程.html" "业务流程"
python -B -X utf8 "<模块目录>/scripts/bpmn_to_png.py" "流程.drawio" "流程.png" "业务流程" 2
```

浏览器按 `--browser`、`BPMN_BROWSER` 环境变量、PATH 和常见安装位置依次查找。需要指定时：

```sh
python -B -X utf8 "<模块目录>/scripts/bpmn_to_png.py" "流程.drawio" "流程.png" "业务流程" 2 --browser "<浏览器可执行文件路径>"
```

HTML 脚本仅用 Python 标准库，支持未压缩单页 XML 中的池/泳道、圆、矩形、菱形、文本、双圈事件与正交折线；保留显式折点，XML 换行分行显示。它不是 draw.io 完整渲染引擎，不承诺复制任意图标、富文本、图片、特殊 `mxgraph.*` 形状或复杂布局。遇到此类元素，使用文字标签加基础形状表达并披露简化，或用用户已有的完整 draw.io 渲染工具；不得静默画错符号。

PNG 使用同一渲染器生成独立工作目录中的 HTML，再截图；工作目录和浏览器资料保留在 PNG 所在目录，供复查，不自动清理。图幅超过脚本尺寸限制时拆图，不能裁掉内容后记作完整交付。

## 5. 交付检查

- XML 可解析，节点 ID 唯一，容器层级无循环，连线端点存在。
- 开始、分支、移交和结束/恢复路径与确认的业务规则一致。
- 浏览器打开 HTML，查看 PNG：角色可读、活动归属正确、条件标签完整、箭头朝向正确、无重叠或裁切。
- 回退线绕开活动；多行文字、中文、矩阵标题和关键异常符号没有丢失。
- draw.io、HTML、PNG 来自同一版源文件；页面缩放或滚动可以查看完整图。
- 未运行的浏览器或图片检查明确标为未验证；不把脚本成功当作视觉验收。

只读查看需求不意味着修改原 PRD。生成图时发现业务缺口，记录问题并等待取舍；已确认的规则变更按跨轮协议检查相关文档、原型和图文件。
