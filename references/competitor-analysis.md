# 竞品分析与本地交付

## 1. 根据目标选择路径

先从用户要求和材料确定要回答的产品问题、比较对象、受众和输出格式。只有产品指代或研究范围的歧义会明显改变结果时才追问。用户要求你推荐对象时，可以按目标用户、用户任务和使用场景选样，并解释入选原因。

| 路径 | 适用输入 | 默认报告内容 |
| --- | --- | --- |
| 材料对比 | 截图、HTML、文档或用户实测记录 | 一页对照，包含范围、场景对照表、差异、可借鉴点和缺口 |
| 公开调研 | 产品名、赛道或需要对标的产品问题 | 简报，包含选样标准、对照结果、关键证据和产品建议 |
| 深度拆解 | 用户要求系统拆解或深度评审 | 行业与竞争范围、产品定位、能力与资源、场景与体验、机会与建议；篇幅按决策目标调整 |

先按入口的模板优先级匹配用户、项目或团队模板。无匹配模板时采用上表的结构。只做一个场景的对标时聚焦该场景，行业规模、商业策略等维度按目标加入。

## 2. 收集证据并比较

1. 有给定材料时，按 [输入处理规范](input-handling.md) 提取来源、观察与缺口。需要在线调研时，使用当前环境可用的公开搜索和网页读取工具，优先查看产品官网、帮助中心、财报或原始研究报告。用户限定只用给定材料时遵守该范围。公开资料读不到时，基于可读资料交付并标出未核实项。证据不足以支撑结论时交付资料缺口和待核验清单。
2. 按同一个用户任务和比较条件检查各对象。注明影响判断的角色、地区、版本、套餐或日期。场景比较可看入口、步骤、关键状态、异常、权限和完成成本。功能没有证据时标为「未核实」。区分厂商声明、材料可见事实、用户提供的实测记录和分析推断。引用关键结论时附链接或文件位置，标明信息日期或版本（如已知）。
3. 先给出回答决策问题的主要发现，再说明差异对用户任务或业务的影响。建议说明借鉴什么、适用条件和待验证事项。未经核验的截图、案例、市场数据或体验结论保留为缺口。
4. 后续如需做方案或 PRD，交接报告版本、来源、主要观察、建议和待验证事项。需要跨轮接续时按 [跨轮协议](cross-round-protocol.md) 记录任务归属及产物依赖。竞品实现记录为外部观察，采纳为我方需求须按项目决策确认。

## 3. 生成本地文件

- 默认写入 UTF-8 Markdown 文件，文件名可用 `<对象或主题>-竞品分析.md`。用户明确要求 HTML 时生成可离线打开的单文件 HTML。其他明确指定的本地格式按 [交付标准](delivery-standards.md) 生成和验证。报告交付在本地完成，禁止通过本流程创建、上传或发布在线文档。公开链接可作为本地报告中的引用来源。
- 路径优先采用用户指定的本地文件或目录。其次用当前项目已有的本地交付目录。任务需要跨轮记录且没有可沿用目录时，按 [跨轮协议](cross-round-protocol.md) 处理。一次性任务没有项目目录时，存入当前任务工作区的 `outputs/`。若当前目录就是技能包目录，选择宿主提供的可写任务工作区。没有可用目录时，请用户指定本地路径。
- 同名文件已经存在时，保留原件并加版本号，除非用户明确要求覆盖。写入后从磁盘重新打开文件，核对路径、正文、对照表及来源，检查证据缺口可见。回复附上本地文件路径、主要发现和影响判断的待核实项。文件未写入时说明原因和当前交付状态。
